Calling an action

Every action is POST $SDEV_URL/v1/robots/$SDEV_ROBOT/<action> with its arguments as a JSON object (all optional unless marked required) and your key in Authorization: Bearer sdev_… (a new key on Your robots). The same action is the MCP tool robot_<action> at $SDEV_URL/mcp, for AI agents. The calls below use these helpers:

{{template "code" .Calling}}

The answer is {"ok": true, …}, or {"ok": false, "error": "…"} with the status 400 (a wrong argument), 401 (no key, or not a valid one), 404 (not this key's robot), 429 (too many: 10 actions a second per key, bursts of 30), 501 (the robot does not offer it) or 503 (the robot is offline).

Also: GET /v1/robots (the key's robot), GET /v1/robots/<robot> (its state, as state), GET /v1/robots/<robot>/events?after=&names=&seconds= (as events), GET /v1/actions (the actions and their arguments as JSON), and /v1/openapi.json: the whole API as OpenAPI 3.1, for API tools and client generators.

{{with part "screen"}}

{{.Name}}

The 320×240 touch screen, with the robot's face. A program puts a card over the face (a title, big text that sizes itself, a note, a progress bar) or a picture; or a speech bubble or an emotion on the face itself. One card at a time: a new one replaces the last, and show with clear brings the face back. Taps on the screen come as events.

{{end}} {{with part "readings"}}

{{.Name}}

The robot reports its sensors every two seconds: the battery and charging, the room light and proximity, the head's angles and its servos' load and temperature, motion and the compass, the clock, Wi-Fi and memory. state returns the latest value of each, the units in their names (battery_pct, light_lux, head_yaw_deg, …), with whether the robot is online, its model, firmware, its own commands and its last events. The robot shows them on its own readings screen too (face with view readings).
